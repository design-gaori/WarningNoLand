### 1-3. 서로 충돌하거나 모호한 부분

1. **화면 구성 범위가 문서 안에서 서로 다릅니다.** 0-4·11-10은 "게임 화면만 구현, 타이틀은 나중에 결정"이라고 합니다. 그런데 7-7·7-8은 성공 화면과 스테이지 선택 화면이 필요하다고 하고, 8-6은 실패 화면이 필요하다고 합니다. 10-1-1은 한 스테이지부터 만든다고 하는데, 10-1-3은 스테이지를 고를 수 있다고 합니다.
2. **조작 안내:** 9-4-1은 "표시 안 함"인데, Figma `stage1` 아래쪽 띠에 안내 문구 2개가 있습니다.
3. **보관 영역의 "보이는 도형 전체"(9-2-8):** Figma에서는 카드가 겹쳐 쌓여 있습니다. 잡는 영역이 카드 전체인지, 콘 그림인지 모호합니다.
4. **연결 판정 순서(5-12 vs 1-4):** BFS 출발점이 "시작 땅 칸"입니다. 시작 땅이 여러 칸이면 모든 시작 칸에서 출발하는 것으로 해석하겠습니다. 이건 가정입니다.
5. **탭 회수와 보관 영역 탭(4-8):** 보관 영역의 콘을 탭했을 때의 동작이 정의되어 있지 않습니다. 저는 아무 일도 일어나지 않게 하는 쪽을 추천합니다.
6. **드래그 중 "화면 밖"(13-4)의 기준:** 브라우저 창 밖인지, 16:9 스테이지 영역 밖인지 모호합니다.
7. **G-2 칸 크기 vs 콘 SVG 크기:** 아래 3-3 참고. 콘 SVG의 바닥 마름모가 0.기본틀보다 약 9% 큽니다.
8. **보관 영역 경계(4-7):** 콘 패턴이 보관 영역에 "걸치면" 배치 불가라고 되어 있습니다. 반응형으로 보관 영역이 보드 위에 겹칠 수 있는지 정해지지 않았습니다.

### 3-3. 기준 칸 `0.기본틀.svg` 확인

  - 웹 페이지가 기기 방향을 강제로 바꿀 수는 없습니다.

  - **iPhone Safari는 방향 잠금 API를 지원하지 않고**, 일반 요소의 전체화면도 지원하지 않습니다.

### 7-1. Outline stroke 점검 결과 (Q9)

선(stroke)이 면으로 변환(outline)되지 않은 파일은 아래 4개입니다. 모두 `stroke-width`를 따로 지정하지 않아서 기본값 1이 적용됩니다.

|---|---|
| `SVG.1/고양이.1.svg` | `.cls-2`, `.cls-4` (#231815) |

### 7-2. 기술 스택 결정 (Q12) — Claude 판단

- **Vite + 순수 TypeScript, 프레임워크 없음**으로 정했습니다.
  - 빌드 결과는 HTML·JS·CSS 정적 파일뿐입니다. 런타임 라이브러리는 0개입니다.
  - JS는 압축된 상태로 수십 KB 수준이 될 것으로 예상합니다. 아직 측정하지 않은 예상치입니다.
  - 로직 테스트는 Vitest를 씁니다. 개발용이라 플레이할 때 로딩에는 영향이 없습니다.
  - 이 PC에 Node.js v24.15.0과 npm 11.12.1이 설치되어 있는 것을 확인했습니다.
- **폰트**는 `@fontsource/outfit`, `@fontsource/nanum-gothic`(800)을 씁니다. 나눔고딕은 글자 범위별로 나뉜 파일 중 화면에 나온 글자가 든 조각만 내려받습니다.
- 위 패키지는 아직 설치하지 않았습니다. 설치할 때 실제로 있는지 확인하겠습니다.
