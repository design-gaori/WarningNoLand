## 4. 질문

1. **스테이지 1 격자**(2장 그림)가 Figma에서 의도하신 모양과 같나요? 55칸, 시작 (0,0), 도착 (13,10)입니다.
2. **기준 칸과 포인터 (4-6):** 기획서는 "포인터가 가리키는 칸에 기준 칸(=가장 위쪽 칸)을 맞춤"입니다. 그런데 콘의 아래쪽을 잡고 끌면, 놓을 때 콘이 잡은 위치보다 위로 튀어 보입니다.
   - (가) 잡은 칸을 기억해서 그 칸이 포인터 칸에 오도록 맞춤 **← 추천**(손가락 아래의 칸이 그대로 따라감)
   - (나) 기획서대로 항상 기준 칸을 포인터 칸에 맞춤
   - 로직 변경은 없고 화면 단계의 계산만 바뀝니다.
3. **패턴 일부만 격자 밖일 때:** 포인터는 격자 안인데 콘의 일부 칸이 격자 밖이면 어떻게 할까요?
   - (가) 원래 자리로(4-7. 보관함에서 꺼냈으면 보관함, 옮기던 콘이면 이전 칸) **← 추천**
   - (나) 무조건 보관함으로
4. **섬이 있는 스테이지의 경로 복원:** 캐릭터 걷기가 빠졌으므로(Q22) 지금은 쓰이는 곳이 없습니다.
   - (가) 섬 스테이지가 생기고 경로가 필요해질 때 정함 **← 추천**
   - (나) 지금 정함. 예: 시작 → 가까운 섬부터 차례로 → 도착

### 5-1. 놓기 규칙 정리 (`dropCone`)

| 놓은 위치 | 보관함에서 꺼낸 콘 | 보드에 있던 콘 |
|---|---|---|
| 놓을 수 있는 빈 칸 | 배치, 수량 −1 | 이동, 수량 그대로 |
| 포인터가 격자 밖 (Q17, Q24) | 보관함 | **보관함**, 수량 +1 |
| 포인터는 격자 안, 패턴 일부가 격자 밖 (답변 3) | 보관함 | **보관함**, 수량 +1 |
| 땅 칸에 걸침 | 원래 자리 = 보관함 | 원래 자리 = 이전 칸 |
| 다른 콘이 있는 칸에 걸침 | 원래 자리 = 보관함 | 원래 자리 = 이전 칸 |

- 3장 I6의 해석은 위 표로 바뀝니다. **격자 밖 관련은 모두 보관함, 땅·찬 칸은 원래 자리**입니다.
