### 2-3. id·클래스 충돌 (중요)

- **41개 파일 모두** 같은 id를 씁니다: `_레이어_2`, `_레이어_1-2`.
- 그라디언트 id가 여러 파일에서 겹칩니다. 예: `_무제_그라디언트_101`은 19개 파일, `_무제_그라디언트_45`는 14개 파일. 겹치는 id는 모두 약 90종입니다.
- clipPath id `clippath`(5개 파일), `clippath-1`(4개 파일)도 겹칩니다.
- **클래스 `.cls-1`~`.cls-65`가 모든 파일에서 서로 다른 색으로 쓰입니다.**

영향:

| 사용 방식 | 충돌 여부 |
|---|---|
| `<img src="…svg">` 또는 CSS 배경 | 충돌 없음. 파일마다 따로 렌더링됨 |
| HTML에 SVG 코드를 직접 넣기(inline) | **충돌 발생.** 마지막에 들어간 파일의 `.cls-N` 색이 다른 콘을 덮어씁니다. 그라디언트·클립도 다른 파일 것이 적용됩니다 |

**"콘 그림만 잡기"(Q15)**를 정확히 하려면 inline이 필요합니다. `<img>`는 투명한 부분까지 사각형 전체가 잡히기 때문입니다. 따라서 **id·클래스에 파일별 접두어를 붙이는 처리**가 필요합니다. → 5장 최적화, 질문 B1

## 3. 기획서 G-11 기준 점검

### 3-1. 콘 그림의 기준 칸 중심 정렬

- **모든 콘의 바닥 칸은 같은 방식으로 정렬되어 있습니다** ✅
  - 가장 아래 칸 중심 → 아래 끝 거리가 74.15로 41개 모두 같습니다(±0.01).
  - 1칸 그림(icon)은 윗면 중심이 가로 정가운데입니다.
  - 그래서 "칸 하단과 콘 하단이 자석처럼 맞닿는" 배치(Q15)를 **같은 계산식 하나로** 할 수 있습니다.
- ⚠️ 원점 기준(viewBox 왼쪽 위)으로 보면 높이가 서로 달라서 중심 y가 132~211로 제각각입니다. **아래 끝 기준으로 맞추면 문제없습니다.**

### 3-2. 칸 크기 — 기준 칸(0.기본틀)과 다름 ⚠️ 가장 중요

| 기준 | 가로 | 세로 | 비율 | 0.기본틀 대비 |
|---|---|---|---|---|
| `0.기본틀.svg` 마름모 | 198.63 | 124.04 | 1.601 | — |
| 콘 SVG의 **칸 간격(격자 한 칸)** | **226.45** | **141.40** | 1.601 | **×1.140** (+27.82 / +17.36) |
| 콘 SVG의 **칸 윗면 그림** | 216.62 | 137.38 | 1.577 | ×1.091 (+17.99 / +13.34) |
| 콘 SVG의 칸 옆면 포함 높이 | 216.60 | 147.33 | — | 두께 약 10 |
| Figma stage1 격자 한 칸 | 236.12 | 147.02 | 1.606 | ×1.189 |

- **콘의 격자 비율(1.601)은 기준 칸과 정확히 같습니다.** 크기만 1.14배 큽니다. 그래서 일정한 비율로 줄이면(Q9 "축소") 격자에 맞습니다.
- **칸 그림(216.6)이 격자 한 칸(226.45)보다 약 9.85 작습니다.** 칸과 칸 사이에 틈이 있도록 그려져 있습니다(Figma 보관 카드에서도 칸 사이에 틈이 보임).
- 그래서 **보드에 얼마나 줄여 놓을지에 따라 결과가 갈립니다.**
  - **(가) 격자 간격 기준으로 맞춤** (보드 칸 236.12 ÷ 226.45 = ×1.043):
    - 여러 칸 콘의 모든 칸이 격자에 정확히 맞습니다.
    - 대신 칸 그림이 보드 칸보다 조금 작아서(225.9 vs 236.12) 칸마다 흰 격자선과 약 5px 틈이 보입니다.
  - **(나) 칸 그림 기준으로 맞춤** (Figma stage1의 1칸 안전콘처럼 그림 = 보드 칸, ×1.090):
    - 1칸 콘은 칸을 꽉 채웁니다.
    - 대신 여러 칸 콘은 칸 간격이 246.9가 되어 **한 칸 갈 때마다 약 10.8px씩 격자에서 밀립니다.** 3칸 콘이면 끝 칸이 20px 넘게 어긋납니다.
  - → 질문 B2

## 5. 최적화(SVGO) — 적용하지 않음, 설명만

### 5-1. 왜 필요한가

- (1) 2-3의 **id·클래스 충돌**을 해결해야 inline으로 쓸 수 있습니다.
- (2) 용량을 줄입니다. 지금 합계는 약 929KB입니다.

### 5-2. 적용하면 생기는 변화

| 처리 | 변화 | 정렬 영향 |
|---|---|---|
| `prefixIds` (기본 설정이 아니라 추가해야 함) | 모든 id와 `.cls-N`에 파일 이름 접두어를 붙임. 예: `cls-1` → `tree__cls-1` | 없음. 충돌 해결 |
| `inlineStyles` (onlyMatchedOnce 끔) | `<style>`의 클래스 색을 각 요소의 `fill` 속성으로 옮기고 클래스 제거 | 없음. 충돌 가능성 자체가 사라짐 |
| 메타데이터 제거 | `data-name`, XML 선언, 한글 레이어 id 제거 | 없음 |
| 숫자 정밀도 줄이기(소수 3자리) | 좌표 반올림. 최대 오차 0.0005 | 사실상 없음(측정 기준 0.01보다 작음) |
| 그룹 정리, transform을 좌표에 합치기 | `<g>` 중첩 축소, transform 제거 | 없음(모양은 같음) |
| 경로 합치기(`mergePaths`) | 색이 같은 경로를 하나로 합침 | 없음. 단, 겹친 순서가 바뀌지 않는 경우에만 합침 |
| **`removeViewBox` — 반드시 끔** | 켜면 viewBox가 지워짐 | ❌ **크기 조절과 기준 칸 정렬이 깨짐.** 사용하지 않음 |
| **`cleanupIds`(id 이름 줄이기)** | prefixIds와 함께 쓰면 그라디언트 참조가 꼬일 수 있음 | 적용 순서를 고정하고 결과를 다시 측정함 |
| `convertShapeToPath`, `removeHiddenElems` 등 | 기본 동작 | 없음 |

- **원본 폴더는 건드리지 않습니다.** `assets/svg/` 복사본에만 적용합니다.
- 최적화한 뒤에는 **2장의 측정(바닥 74.15, 중심 108.81, 칸 간격 226.45×141.40)을 다시 실행해** 값이 그대로인지 확인합니다.
- 예상 용량 감소: 아직 **측정하지 않았습니다.** 적용해서 실제 수치를 보고하겠습니다.
- SVGO는 개발용 도구로만 설치합니다(게임 실행에 포함되지 않음).
