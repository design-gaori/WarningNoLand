# 스테이지 추가 가이드 (STEP 11)

> 사람과 Claude Code가 함께 읽는 문서입니다. 스테이지를 추가할 때 **먼저 이 문서를 읽고**, 아래 순서를 따릅니다.
> 코드는 고치지 않고 **데이터 파일 하나만 추가**하는 것이 기본입니다.

## 1. 추가 순서

1. Figma에서 새 스테이지 프레임(예: `stage2`)을 확인합니다.
   - 흰 마름모 칸 = 배치할 수 있는 빈 칸(Q6). 이 밖에 칸을 **임의로 추가하지 않습니다.**
   - 위쪽 끝 콘 = 시작 땅, 아래쪽 끝 콘 = 도착 땅(Q10).
   - 보관 카드에 보이는 콘 종류와 `n/m`의 m(처음 수량)을 적습니다(Q14).
2. `data/stages/stage-N.json` 파일을 만듭니다. `stage-1.json`을 복사해 고치면 됩니다(2장 형식).
3. 자동 점검을 돌립니다.
   ```bash
   npm test
   ```
   `tests/stages.test.ts`가 새 파일을 **자동으로 찾아** 3장의 규칙을 모두 검사합니다.
4. 화면에서 확인합니다.
   ```bash
   npm run dev
   ```
   - `http://localhost:5173/?screen=stage&stage=stage-N`: 빈 보드
   - `...&demo=1`: 예시 해답을 미리 놓은 상태(앞뒤 가림 확인용)
   - `?screen=select`: 선택 화면에서 표지판이 눌리는지
   - 창 크기 1920×1080, 2240×1150(주소창 있는 아이맥), 1440×780, 휴대폰 가로에서 확인
5. 점검이 실패하면 **데이터를 억지로 맞추거나 코드를 바꾸지 말고**, 4장 표를 보고 사용자에게 먼저 묻습니다.

## 2. 데이터 형식

```jsonc
{
  "$comment": "출처(Figma 프레임·노드 id)와 가정을 적는다",
  "id": "stage-2",            // 파일 이름과 같게 (stage-2.json)
  "name": "Stage 2",          // 선택 화면 표지판 글자
  "cells": [[1,0], [2,0]],    // 배치 가능한 빈 칸 [열, 행] 목록 (Q21)
  "start": [[0,0]],           // 시작 땅. 항상 (0,0) = 맨 위
  "end":   [[13,10]],         // 도착 땅
  "islands": [],              // 중간 섬 — 지금은 비워 둔다 (4장)
  "cones": [                  // 보관 카드 순서 = 이 순서 (위 → 아래)
    { "coneId": "tree", "count": 5 }
  ],
  "exampleSolution": [        // 필수. 기준 칸(anchor) = 그 콘 패턴의 (0,0) 칸
    { "coneId": "tree", "anchor": [1,0] }
  ]
}
```

- **좌표 재는 법:** Figma 격자 한 칸은 236.121 × 147.019입니다. 시작 땅 칸의 중심을 (0,0)으로 두고 계산합니다.
  - 열 = (dx / 118.06 + dy / 73.51) / 2
  - 행 = (dy / 73.51 − dx / 118.06) / 2
  - dx, dy는 시작 땅 중심에서 그 칸 중심까지의 거리입니다. 결과가 정수에서 0.05 이상 벗어나면 Figma를 다시 확인합니다.
- **콘 id(20종):**
  - `cake` `cat` `cheese` `easel` `fire-hydrant`
  - `flower-pot` `french-fries` `hat` `ice-cream` `lamp`
  - `person` `poop` `safety-cone` `sign-board` `soju`
  - `traffic-light` `trash-can` `tree` `umbrella` `wine`
  - 모양(칸 패턴)은 `data/cones.json`에 있습니다.
- 형식이 틀리면(없는 콘, 칸 중복, 땅과 격자 겹침 등) 읽을 때 오류가 납니다. **이 오류는 게임 전체를 멈추게 하므로** 반드시 `npm test`로 먼저 확인합니다.

## 3. 자동 점검 (`tests/stages.test.ts`)

| 점검 | 왜 필요한가 |
|---|---|
| 파일 이름 = id, id 중복 없음 | 선택 화면 순서와 화면 이동이 id로 동작 |
| 스테이지 수 ≤ 선택 화면 표지판 수(지금 2개) | 넘치면 그 스테이지로 갈 방법이 없음 |
| 중간 섬 없음 | 섬 그래픽·규칙 미정 |
| 콘 종류 ≤ 3 | 보관 카드 디자인이 3장 기준(4장이면 카드가 너무 작아짐) |
| 시작·도착 땅이 격자 칸과 변을 공유 | 이어질 수 없는 스테이지 방지 |
| 모든 칸의 (열+행) ≥ 0 | 시작 땅보다 위로 칸이 있으면 화면 위에서 잘림 |
| 보드 왼쪽 끝 ≥ 0, 오른쪽 끝 ≤ 1587 | 화면 왼쪽 밖·보관 카드 밑으로 들어가지 않게 |
| 보드가 BACK·RESTART 자리와 겹치지 않음 | 버튼 밑에 칸이 숨지 않게 |
| 예시 해답으로 성공 | 풀 수 있는 스테이지인지 확인(15-3) |
| 처음 상태에서는 연결 안 됨 | 시작하자마자 Game Clear가 뜨지 않게 |
| 콘 20종의 piece·icon SVG가 모두 있음 | 그림 누락 방지 |

- 세로 길이는 제한하지 않습니다. 도착 땅 위치에 맞춰 스크롤 길이가 자동으로 정해집니다(`contentHeight`).

## 4. 점검이 실패하거나 아래에 해당하면 — 먼저 사용자에게 질문

| 상황 | 지금 상태 | 필요한 결정 |
|---|---|---|
| 3번째 스테이지부터 | 선택 화면 표지판이 Stage 1(삼각형)·Stage 2(원) 2개뿐(`selectScreen.ts`의 `SLOTS`) | Figma 선택 화면 새 디자인 |
| 중간 섬이 있음 | 섬 칸에 격자선만 그림. 경로 복원(`findPath`)은 섬이 있으면 예외 | 섬 그래픽(BOARD_NOTES 질문 1) |
| 콘 종류 4개 이상 | 카드가 계속 작아짐 | 카드 배치 디자인 |
| 보드가 화면 밖·카드 밑·버튼 밑 | 모든 스테이지가 stage1의 보드 시작점(`layout.ts`의 `board.originX/Y`)을 같이 씀 | 스테이지별 보드 위치를 둘지 |
| Figma 새 프레임의 구름·점 위치가 stage1과 다름 | 구름·점·버튼·카드 위치는 모든 스테이지가 `STAGE1_LAYOUT`을 같이 씀 | 스테이지별 배치 값을 둘지 |
| 시작·도착 땅이 여러 칸이거나 콘이 아닌 그림 | 땅 그림 = `icon/safety-cone.svg` 한 칸짜리(A1) | 땅 그래픽 |

## 5. 하지 말 것

- `stage-1.json`과 원본 에셋 폴더는 고치지 않습니다.
- 점검을 통과시키려고 `tests/stages.test.ts`의 기준값을 바꾸지 않습니다. 기준을 바꾸는 것은 디자인 결정이므로 사용자 확인이 필요합니다.
- Figma에 없는 칸·콘·버튼을 추가하지 않습니다.
